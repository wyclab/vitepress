# AI 核心概念

> 现在的 AI 圈每天都在冒新词：Model、Agent、Skill、Harness、MCP、Context Engineering……其实剥开外壳，它们共同拼装的只是同一台机器。这篇文章用最直白的方式，先把最核心的几个概念以及它们的关系讲清楚（后续按需持续补充）。

---

## 一张图看懂核心关系

在当代 AI 工程中，有一个被反复验证的核心公式：

```text
Agent（智能体） = Model（模型） + Harness（驾驭层）
                                    ├── Tools / MCP（手脚与外设接口）
                                    └── Skills（按需翻阅的 SOP 技能包）
```

如果把一整套 AI 系统比作**“一位能独立干活的资深员工”**，每个概念扮演的角色一目了然：

| 概念 | 中文常译 | 形象比喻 | 一句话定义 |
| --- | --- | --- | --- |
| **Model** | 大模型 | **大脑 / 智商** | 负责理解、推理与生成内容，但本身是静态的“缸中之脑”，不能直接操作外界。 |
| **Harness** | 驾驭层 / 运行时框架 | **身体 + 工位 + 规章制度** | 包裹在模型外围的软件脚手架，负责循环驱动、沙箱执行、上下文压缩、记忆与安全审批。 |
| **Skill** | 技能 | **岗位 SOP 手册 + 专用脚本** | 封装好的特定任务知识与流程包，由 Harness 在需要时按需加载，教模型把某类事做专业。 |
| **Tool / MCP** | 工具与协议 | **电脑、终端、浏览器与 USB-C 接口** | 模型能调用的外部能力（查资料、改文件、跑命令等），MCP 则是连接它们的统一接口标准。 |
| **Agent** | 智能体 | **完整的“数字员工”** | 以上全部合体后的运行实体——能听懂目标、自己拆步骤、动手干活、看报错并纠偏，直到交付结果。 |

---

## Model（模型）

**Model（大语言模型 / 多模态模型）** 是整个系统的智力引擎，比如 Google Gemini 4、OpenAI GPT-6、Anthropic Claude 5、DeepSeek V4 等（各家具体型号可见 [模型介绍](/articles/ai/ai-tech/model-intro)）。

从工程视角看，理解 Model 只需抓住两点：

1. **本质是“无状态的大脑”**：你给它一段输入（文本、图片、代码），它根据训练学到的知识与推理能力，输出下一段内容或“我想调用某个工具”的意图。一旦这次请求结束，模型本身**不会记住任何事**，也没有权限直接碰你的硬盘或网络。
2. **三大核心维度**：
   - **智力上限与推理深度（Thinking）**：能不能拆解复杂逻辑、少犯低级错误；如今主流模型普遍支持按需调节思考深度（如 `low` / `medium` / `high`）。
   - **上下文窗口（Context Window）**：一次对话最多能“同时看进脑子里”的信息量（2026 年主流旗舰已普遍迈入 100 万 Tokens 级别）。
   - **速度与成本**：决定它适合做高频干活的“快手”，还是攻坚难题的“总设计师”。

---

## Agent（智能体）

很多人容易把 **Agent** 和普通的 **Chatbot（聊天机器人）** 混为一谈。两者的分水岭其实非常简单：

- **Chatbot（一问一答）**：你问一句，它答一句，执行动作靠你自己复制粘贴去完成。
- **Agent（目标闭环）**：你只给一个**目标**（例如：“把项目里的登录 Bug 修好并跑通单元测试”），它会自主经历 **「规划 → 调工具执行 → 观察反馈 → 发现报错自我修正 → 再次验证」** 的多轮闭环，直到任务真正完成才交卷。

**从单兵到团队的演进**：当任务过于庞大时，一个 Agent 容易顾此失彼，于是衍生出 **Subagent（子智能体）** 与 **Swarm（多智能体蜂群）**——由一个主控 Agent 拆分任务，派发给多个并行工作的子 Agent 分头调研、写代码或做交叉审查，最后汇总验收。当前主流的编程、个人与通用 Agent 产品盘点，可继续阅读 [AI Agent介绍](/articles/ai/ai-tech/agent-intro)。

## Harness（驾驭层 / 运行时脚手架）

**Harness** 是近年 AI 工程领域含金量最高、也最容易被普通用户忽略的概念。英文原意是**“马具 / 挽具 / 测试台架”**——再强壮的千里马（Model），如果没有缰绳、马鞍和车架（Harness），也没法拉车上路。

如果说 Model 决定了能力的**理论下限与天花板**，那么 **Harness 决定了 AI 在真实世界里到底好不好用**。像 Claude Code、Cursor、Antigravity 这类顶流 AI 开发工具，本质上都是在做极其精良的 Agent Harness。

一个成熟的 Harness 通常包揽五大脏活累活：

1. **执行循环（Agent Loop）**：替模型维持一个永不停歇的“思考 → 调工具 → 拿结果 → 再思考”主循环，直到任务达标或触发停止条件。
2. **沙箱与工具运行时（Sandbox & Runtime）**：提供安全隔离的文件读写、终端命令执行和浏览器操作环境，让模型真能动手，又不会一把删库跑路。
3. **上下文管理与压缩（Context & Compaction）**：长任务跑久了对话会越来越长，不仅烧钱，还会触发**“上下文腐烂（Context Rot）”**（信息太多导致模型变笨、忘事）。Harness 会在后台自动裁剪冗余日志、总结历史进度，让模型始终保持清醒。
4. **状态与记忆持久化（Memory & State）**：把会话进度、用户偏好、项目规范沉淀到磁盘文件或数据库中，让“健忘的模型”跨天、跨会话依然记得你的习惯。
5. **安全护栏与审批流（Guardrails）**：用确定性的程序代码卡死边界——读文件可以直接放行，但执行外部网络请求、付费操作或危险命令时，强制暂停并弹窗请人类点确认。

> **行业共识：“同模型，不同 Harness，表现天差地别。”** 很多时候换一个工具觉得“AI 突然变聪明了”，底层模型其实一个权重都没变，真正拉开差距的是外层的 Harness 工程。

## Skill（技能）

有了 Model、Harness 和各种基础工具后，很快会遇到一个新痛点：

> 团队里有很多专业流程（比如“按公司规范写周报”“做一套合规的数据库迁移”“把旧配置文件迁移成新格式”）。如果把几十套流程规范全部塞进系统提示词里，上下文立刻爆炸，模型注意力也会被稀释。

**Skill（技能）** 就是为了解决这个问题而生的**模块化能力封装包**：

- **长什么样**：通常是一个轻量目录，核心是一份结构化的指令说明书（如 `SKILL.md`），按需附带现成的辅助脚本、模板文件或参考资料。
- **核心机制——渐进式披露（Progressive Disclosure）**：这是 Skill 与 Harness 配合最精妙的地方。平时模型只看到一行极简的“技能名称 + 简介”，几乎不占上下文；**只有当用户的请求命中某个场景时，Harness 才会按需把对应的 `SKILL.md` 完整内容和脚本调出来喂给模型**。
- **直白理解**：Tool 给模型的是“原子动作”（能敲命令、能读写文件），而 **Skill 给模型的是“行业 Know-How 与标准作业程序（SOP）”**。写好一个 Skill，就相当于把一位老专家的经验打包成插件，任何兼容的 Agent 装上就能立刻按高标准干活。

## 几个高频配套概念（速查）

日常看技术文章或折腾 AI 工具时，还会高频碰到下面这几个“胶水词”，顺手一并捋清：

- **Prompt / System Prompt（提示词 / 系统提示词）**：你对模型说的话叫 Prompt；由开发者或 Harness 提前写好、用来设定 AI 角色、规矩与边界的“后台隐藏指令”叫 System Prompt。
- **Context Engineering（上下文工程）**：从早年的“研究怎么写一句好提示词（Prompt Engineering）”，升级为系统性地设计“在每一步该把什么信息、以什么格式、多精简地放进模型视野里”。
- **MCP（Model Context Protocol，模型上下文协议）**：AI 世界的 **“USB-C 接口标准”**。过去每个 AI 应用接数据库、GitHub、飞书都要各自写一遍对接代码；有了 MCP 后，工具方按统一协议封装一次，所有支持 MCP 的 Agent 都能即插即用。
- **Workflow（工作流） vs. Agent（智能体）**：Workflow 是人类提前画死流程图（第 1 步干嘛、第 2 步干嘛，确定性高、适合固定流水线）；Agent 是只给目标、由模型自己临场决定怎么走（灵活度高、适合开放复杂任务）。实际落地中往往是两者混用。

---

> 记住主干脉络就不会迷路：**Model 是大脑，Harness 是身体与机制，Tools/MCP 是手脚，Skill 是按需翻阅的专业手册，它们合在一起，才构成了能真正替你干活的 Agent。**
